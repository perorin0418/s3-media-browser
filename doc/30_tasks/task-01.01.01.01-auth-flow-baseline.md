# Task

## Task 名
- ID: task-01.01.01.01-auth-flow-baseline
- 所属 Feature: feature-01-01-01-auth-and-access-baseline

## 作業目的
CDK で構築した Cognito と Hosted UI を前提に、認証導線と認証状態の取得を成立させ、未認証の閲覧入口アクセスを遮断できる基盤を整える。

## 作業内容
- CDK 構成として Cognito と Hosted UI を利用可能な状態に整備する
- フロントエンドのサインイン入口とコールバック受け口を用意し、認証状態を取得できるようにする
- 閲覧 UI の表示前に認証状態を検証する前提を整え、未認証時の遮断経路を確定する
- S3 関連 API 呼び出しに認証コンテキストを付与できる受け口を準備する
- 認証状態の不確実性がある場合はフェイルクローズ前提で扱う

## 実装制約
- Cognito は CDK で構築し、Hosted UI を標準フローとして採用する
- 既存の権限モデルは拡張・変更しない
- 未認証時にメディアのメタデータやオブジェクト情報を返さない
- S3 への具体的な認可ロジックは本 Task の対象外とする

## 変更対象
- infra/ の Cognito および Hosted UI 設定を管理する CDK スタック
- frontend/ の認証入口（サインイン/コールバック）と認証状態参照の UI モジュール
- backend/ の S3 関連 API 呼び出しに認証コンテキストを受け渡す層

## 非変更対象
- 既存の権限モデル定義とそのルール
- S3 への具体的な認可アルゴリズム
- API/スキーマ仕様（interfaces）やアーキテクチャ構成

## テスト観点
- infra/ の CDK で Cognito/Hosted UI が期待通りに構成されること
- frontend/ のサインイン入口からコールバックまでの導線が成立すること
- frontend/ の未認証時に閲覧入口が遮断されること
- backend/ の S3 関連 API で認証コンテキストが利用可能であること
- 認証状態が不確実な場合にフェイルクローズとなること

## 完了条件
- Hosted UI によるサインインが可能で、認証状態を取得できる
- 未認証ユーザーは閲覧入口へアクセスできない
- API へ認証コンテキストを付与する入口が準備されている
- 認証不確実時はアクセスが拒否される
